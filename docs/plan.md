# Project Plan

**Project:** Isaac Ihebom | Personal Profile (CMPA 3301)
**Repository:** https://github.com/WrldofIsaac/CMPA-3301

## 1. Project Summary

This project is a single-page personal profile website built with HTML and CSS, supported by Markdown documentation. The page introduces who I am, my major (Computer Applications and Legal Studies), my career goals in cybersecurity, my hobbies, and a link to my GitHub profile.

## 2. Work Breakdown Structure (WBS)

My work is broken into phases, and each phase is broken into tasks small enough to finish in one sitting.

### 1. Planning and Scope
- Brainstorm what the page should say about me
- Write the project scope statement
- look over the scope based on peer feedback
- Write this project plan

### 2 Repository Setup
- Create the public GitHub repository
- Create the folder structure like index, style ccs and docs/ file
- Create Readme file

### 3. Content and Structure (HTML)
- Create the basic layout head, header, main and footer
- Write the "About me" section (major, goals, career path)
- Add the "My hobbies" section (fishing, guitar, hunting)
- Add the footer with the GitHub profile link

### 4. Design and Styling (CSS)
- Choose colors and fonts
- Style the masthead, sections, and typography
- Make the layout responsive for small or big screens

### 5. Testing and Review
Proofread all text (page, README, scope)
- 5.2 Check the page at desktop and phone sizing
- 5.3 Click-test every link
- 5.4 Validate the HTML link

### 6.0 Publishing and Documentation
- Site my actual link through the readme file.
- Move my remaining files into docs/ folder
- 6.4 Write the retrospective

## 4. Risk Analysis (TAME Framework)

Each risk is rated for likelihood and impact (Low, Medium, High) and given a TAME response: **T**ransfer, **A**ccept, **M**itigate, or **E**liminate.

| # | Risk | Likelihood | Impact | TAME response | Action |
|---|------|-----------|--------|---------------|--------|
| 1 | I run out of time because of other classes and the end-of-semester workload | Medium | High | **Mitigate** | Work in the phases above, finish the important parts first, and keep documentation for the end. Stick to the scope's exclusions. |
| 3 | Layout breaks on phones or different browsers | Medium | Medium | **Mitigate** | Test at desktop and phone widths before publishing. |
| 4 | Typos and unclear wording make the page look careless (the scope draft already had a few) | High | Medium | **Mitigate** | Proofread every file and read the text out loud before submitting. |
| 8 | Personal information shared publicly (career plans, hobbies) is more than I want online | Low | Medium | **Eliminate** | Keep the page to information I'm comfortable sharing. No address, or phone numbers. Maybe strictly an email or social media. |
| 9 | I lose work because of a device problem | Medium | High | **Transfer** | The repository on GitHub holds a copy of the work, so the risk is transferring. I will have to push and commit anytime I finish a thought. | 
| 10 | Peer feedback allows for greater changes | Low | Medium | **Accept** | Small revisions to the scope and page have already been done. But if feedback is bigger than I expect, I will need to prioritize what best fits the assignment requirements. |

## 5. Success Criteria

The project is complete when:

- The repository is public and contains README.md and a docs/ folder with scope.md, plan.md, and retrospective.md
- The README explains the purpose and links to the live website and the documentation folder
- The live site loads, shows my name, major, goals, hobbies, and GitHub link
- All content stays within the scope's exclusions
- The page sounds personal and natural, as the scope describes
